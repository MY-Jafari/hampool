# وایرفریم و نقشه‌ی صفحات فرانت‌اند همپول

> مبنای این سند: `API_SUMMARY.md` (تحلیل بک‌اند واقعی).
> نسخه‌ی ۱ — منتظر بازخورد شما قبل از کدنویسی.

---

## ۰. ساختار کلی

```
[AppShell]
 ├─ سایدبار دسکتاپ (راست) / ناوبری پایین موبایل
 │   داشبورد · گروه‌ها · پروفایل
 ├─ هدر: عنوان صفحه · زنگوله اعلان (WS) · منوی کاربر
 └─ <محتوای صفحه>  (loading / error / empty state برای هر داده)
```

- **RTL کامل** (direction، آیکون‌ها، انیمیشن‌ها، spacing — نه فقط `rtl` روی متن).
- **موبایل‌فرست:** ستون‌ها روی موبایل تک‌ستون می‌شوند، سایدبار → ناوبری پایین.
- وضعیت سه‌گانه برای هر داده‌ی API: `skeleton loading`، `error + دکمه تلاش مجدد`، `empty state طراحی‌شده`.

## ۱. ورود (`/login`)

```
┌──────────────────────────────┐
│  همپول 💰                     │
│  ورود به حساب                │
│  شماره موبایل  [09xxxxxxxxx] │
│  رمز عبور      [••••••••]    │
│  [ ورود ]                    │
│  حساب ندارید؟ ثبت‌نام         │
└──────────────────────────────┘
```
- لاگین با `{phone_number, password}` → ذخیره access/refresh.
- خطای Rate-Limit: بنر «درخواست‌های زیاد؛ کمی صبر کنید و دوباره تلاش کنید».
- خطای اعتبارسنجی زیر هر فیلد (فارسی).

## ۲. ثبت‌نام ۲ مرحله‌ای (`/register`)

**مرحله ۱ — اطلاعات:**
```
┌──────────────────────────────┐
│  ساخت حساب جدید              │
│  شماره موبایل  [09xxxxxxxxx] │
│  رمز عبور      [••••••••]    │
│  تکرار رمز     [••••••••]    │
│  [ ثبت‌نام و دریافت کد ]     │
└──────────────────────────────┘
```
- ارسال `{phone_number, password, password_confirm}` → ذخیره `temp_token`.

**مرحله ۲ — کد OTP (همان صفحه، استپ‌ایندیکیتور):**
```
┌──────────────────────────────┐
│  ① اطلاعات ✓  ② کد تایید     │
│  کد ۶ رقمی را وارد کنید      │
│  [ ۵ ۲ ۸ 3 0 1 ]  (ورودی ۶) │
│  [ تایید و ورود ]            │
│  ⓘ (توسعه): کد در کنسول      │
│    بک‌اند چاپ می‌شود          │
└──────────────────────────────┘
```
- ارسال `{code}` با هدر `Authorization: Bearer <temp_token>` → دریافت access/refresh → لاگین.

## ۴. گروه‌ها (`/groups`)

- لیست کارتی گروه‌ها (نام، توضیح، تعداد عضو، مجموع هزینه، وضعیت بودجه، موجودی من).
- **مودال ساخت گروه:** نام، توضیح، بودجه + دکمه `🤖 پیشنهاد نام با AI` (سه نام فارسی/انگلیسی قابل انتخاب).
- **دیالوگ عضویت با کد دعوت:** ورودی ۸ کاراکتری.

## ۵. جزئیات گروه (`/groups/:id`)

### تب «نمای کلی»
```
مجموع هزینه: ۱٬۲۴۰٬۰۰۰    بودجه: ۵٬۰۰۰٬۰۰۰    باقی: ۳٬۷۶۰٬۰۰۰
[ 🤖 پیشنهاد تسویه بهینه ]

موجودی اعضا
┌────────────────────────────────────────┐
│ علی  (0912...)      +۷۲۰٬۰۰۰  طلبکار 🟢 │
│ سارا (0935...)      −۴۰۰٬۰۰۰  بدهکار 🔴 │
│ من   (0912...)      −۳۲۰٬۰۰۰  بدهکار 🔴 │
└────────────────────────────────────────┘
```
- پیشنهاد بهینه: `GET optimize-settlements/` → لیست «X → Y مبلغ» + دکمه «ایجاد تسویه‌ها» (با `balance_version`؛ در صورت `409` پیام و تلاش مجدد).

### تب «هزینه‌ها»
- لیست: توضیح، مبلغ، پرداخت‌کننده، نوع تقسیم، وضعیت تایید، تاریخ.
- دکمه «تایید» (فقط پرداخت‌کننده/admin) و «حذف».
- **فرم ثبت هزینه (مودال):**
  - توضیح، مبلغ کل، نوع تقسیم (۴ گزینه)
  - `مساوی`: انتخاب اعضا (سهم خودکار)
  - `دقیق`: انتخاب عضو + مبلغ سهم
  - `درصدی`: انتخاب عضو + درصد (جمع باید ۱۰۰)
  - `آیتمی`: چند آیتم (نام + مبلغ + سهم هر عضو)
  - ضمیمه رسید (اختیاری، `receipt_image`)

### تب «تسویه‌ها»
- لیست: از → به، مبلغ، وضعیت (`در انتظار`/`تایید شده`/`ابطال شده`)، تاریخ.
- دکمه «تایید» (فقط گیرنده)، «ابطال» (دو طرف).
- دکمه «تسویه جدید»: انتخاب گیرنده (طلبکار) + مبلغ.

### تب «اعضا»
- لیست اعضا + نقش (admin/member) + تاریخ عضویت.
- «افزودن عضو» با شماره موبایل (admin).
- تغییر نقش / حذف عضو (admin) — حذف خود برای همه.
- **دعوت:** کد دعوت + نمایش QR (تصویر از `qr-code/` با fetch-authenticated) + دکمه «کپی لینک».

### تب «فعالیت‌ها»
- لیست لاگ: `{user_phone} — {action} — {description} — {timestamp}`.

### تب «گزارش‌ها»
- نمودارها (Recharts، ساخته‌شده از داده‌ی واقعی هزینه‌ها):
  - هزینه‌ی روزانه (۷ روز اخیر) — Bar
  - ترکیب هزینه‌ها بر اساس نوع تقسیم — Pie
  - سهم اعضا از هزینه‌ها — Bar
- دکمه «درخواست گزارش PDF» → `POST report/` → toast «گزارش به ایمیل شما ارسال می‌شود».

## ۶. پروفایل (`/profile`)

- نمایش شماره (غیرقابل تغییر)، ویرایش نام/ایمیل/زبان (fa/en)، آپلود آواتار.
- دکمه «خروج از حساب» (بلاک‌لیست refresh → حذف توکن‌ها → رفتن به ورود).

---

## ۷. مرکز اعلان (کامپوننت در هدر)

- زنگوله با نشان تعداد خوانده‌نشده.
- پنل کشویی: رویدادهای زنده‌ی WebSocket با متن فارسی ساخته‌شده از `event_type` + `params`:
  - `member_joined` → «علی به گروه پیوست»
  - `expense_created` → «علی هزینه‌ی «شام» به مبلغ ۲۵۰٬۰۰۰ ثبت کرد»
  - `settlement_confirmed` → «تسویه‌ی ۸۰٬۰۰۰ تومان تایید شد»
  - و...
- بعد از هر رویداد: re-fetch داده‌ی گروه (best-effort بودن پیام‌ها).
- اعلان‌ها فقط در حافظه‌ی کلاینت (بک‌اند ذخیره نمی‌کند).

---

## ۸. دستیار AI (ویجت)

- دکمه `🤖 پیشنهاد نام با AI` در مودال ساخت گروه و ویرایش گروه.
- خروجی: ۳ نام فارسی + ۳ نام انگلیسی → کلیک = انتخاب.

---

## ۹. حالت‌های خاص

- **۴۰۴** → صفحه‌ی «گروه پیدا نشد / صفحه وجود ندارد» با لینک بازگشت.
- **Empty states:** بدون گروه → «اولین گروه را بسازید» + اکشن. بدون هزینه → «هنوز هزینه‌ای ثبت نشده».
- **Skeleton:** کارت‌ها/لیست‌ها هنگام لود.
- **خطای عمومی API:** toast با پیام استخراج‌شده از `detail`/`error`/`field errors`.
